## 摘要
紧凑的动态场景表示必须同时保留随时间观察到的表面，以及从新视角渲染这些表面所需的外观。我们提出 Sparc4D，一种前馈自编码器，可将已知相机参数的单目视频编码为稀疏的4D场景状态。静态特征在整个视频片段中共享，而空间锚定的时间槽压缩随时间变化的特征。稀疏解码器生成2D高斯面元（surfels），同时存储的源像素通过几何重投影保留精细纹理。该状态包括一帧完整源帧和每四帧采样的动态区域像素，以及学习到的特征和稀疏占据信息。对于32帧的MultiCamVideo片段，在随机窗口上平均为0.95M个32位等效值，在 first-32 协议上为0.92M。在 first-32 上，Sparc4D达到21.70 dB，而MoVieS为20.40 dB。在随机放置的窗口上，它们的PSNR分数相当。在禁用存储纹理的情况下，时间槽将随时间变化的特征状态以中位数 $4.0\times$ 压缩，并将平均状态从1.04M个值减少到0.42M个值，而目标视角重建质量基本不变。在未在真实数据上微调的情况下，Sparc4D可迁移到DyCheck和Neu3D，其中存储纹理会改善LPIPS，同时略微降低PSNR。

## Abstract
A compact dynamic-scene representation must retain both the surfaces seen over time and the appearance needed to render them from new viewpoints. We present Sparc4D, a feed-forward autoencoder that encodes a monocular video with known cameras into a sparse 4D scene state. Static features are shared across the clip, while spatially anchored temporal slots compress time-varying features. A sparse decoder produces 2D Gaussian surfels, while stored source pixels preserve fine texture through geometric re-projection. The state includes one full source frame and dynamic-region pixels sampled every fourth frame, alongside learned features and sparse occupancy. For a 32-frame MultiCamVideo clip, it averages 0.95M 32-bit-equivalent values on random windows and 0.92M on the first-32 protocol. On first-32, Sparc4D reaches 21.70\,dB, compared with 20.40\,dB for MoVieS. On randomly placed windows, their PSNR scores are comparable. With stored texture disabled, temporal slots compress the time-varying feature state by a median $4.0\times$ and reduce the mean state from 1.04M to 0.42M values, with essentially unchanged target-view reconstruction quality. Without fine-tuning on real data, Sparc4D transfers to DyCheck and Neu3D, where stored texture improves LPIPS while slightly reducing PSNR.

## 1. 核心问题与整体含义

- **研究动机**：前馈式重建方法能从单目视频恢复动态场景并渲染新视角，但**场景表示本身与重建过程同样重要**——它必须跨时间保留信息，同时足够小以便存储与复用。
- **核心矛盾**：
  - 像素对齐高斯方法（如 MoVieS）在运动被物化到整个片段时会产生**巨大的输出状态**（719M 值）。
  - 紧凑高斯预测器（如 C4G）减少了图元数量，但揭示了**表示规模与重建保真度之间的权衡**。
  - 视频 tokenizer 能压缩图像序列，但像素空间输出**不提供显式 3D 渲染接口**；稀疏 3D 自编码器提供结构，但未解决动态场景中"哪些信息共享、哪些随时间变化"的问题。
- **整体含义**：论文将问题拆解为两个需求分别处理——静态内容跨片段共享、精细外观单独保留——目标是编码出一个**紧凑、显式、可解码为高斯面元进行新视角渲染的 4D 场景状态**。

## 2. 方法论

### 2.1 核心思想
- 构建一个**前馈自编码器**，将已知相机位姿的单目视频编码为稀疏 4D 场景状态。
- 静态观测共享一个跨片段的隐表示；动态观测先逐帧编码，再压缩为每个被占据潜在单元上的少量**时间槽（temporal slots）**。
- 解码器输出 **2D 高斯面元（surfels）** 进行显式渲染；另设一条**存储源像素纹理**路径，通过几何重投影保留精细纹理。

### 2.2 关键技术细节

**（1）场景观测构建（Sec. 3.1）**
- 输入 T=32 帧 256×256 RGB，已知内参与世界-相机位姿；用 **Depth Anything 3** 估计深度。
- 像素反投影到世界坐标：$p_t(x) = R_t^\top (D_t(x)K^{-1}\tilde{x} - t_t)$，每个点携带 RGB、深度导出法线与位置。
- **静态/动态分离**：测试某点的预期位置是否被另一帧"看穿"；用前景物体掩码将运动种子扩展到整个物体（含短暂静止时段）。
- 在场景自适应立方体中以 **512³ 分辨率体素化**；更大更粗的立方体存外部静态点；等距柱状环境贴图存远处观测；未被覆盖像素填源视频均值颜色。
- 每个被占据体素存均值 RGB、均值法线、体素内偏移；八分体颜色残差保留子体素变化。

**（2）共享静态特征与时间槽（Sec. 3.2）**
- 从 **TRELLIS.2 形状自编码器**初始化稀疏编解码器，将 512³ 稀疏体素映射为 32³ 网格上的 32 通道潜在。
- 静态、粗背景、逐帧动态张量共享同一网络权重；静态与粗背景潜在每片段存储一次。
- 动态特征压缩：设 $U$ 为全片段动态潜在单元并集，$z_{u,t}$ 为单元 $u$ 在时刻 $t$ 的潜在，压缩为每单元 2 个槽：
  - $k_{u,t} = Wz_{u,t} + \phi_t(t) + \phi_p(u)$
  - $A_u = \text{Attn}(Q + \phi_p(u), \{k_{u,t}\})$
  - $\{S_u\} = \text{Proj}(\text{Mix}(\{A_u\}))$
  - 解码：$\hat{z}_{u,t} = \text{Dec}(\phi_t(t) + \phi_p(u), S_u)$
- 状态存储 $2|U|$ 个潜在向量，而非所有逐帧向量。

**（3）外观与面元解码（Sec. 3.3）**
- 32³ 潜在网格中一个单元跨 16³ 输入体素，故在 **128³ 网格上存 16 通道外观码**提供更精细纹理路径：
  - $a_u = W_e\,\text{LN}(e_u)$，$g_u \leftarrow g_u + \gamma W_d a_u$
- 每个解码体素发射 **4 个 2D 高斯面元**（degree-1 球谐颜色），预测中心偏移、尺度、旋转、不透明度的残差（相对面向相机的基准配置）；用 gsplat 光栅化。
- 动态解码使用**查询时刻观测到的占据**，当前模型仅支持观测时间戳上的新视角。

**（4）存储源像素纹理（Sec. 3.4）**
- 存储第一帧完整 RGB + 每第 4 帧的动态区域像素（动态区域 = 解码动态层源视角不透明度 >0.5 并膨胀 2 像素，已存储的像素不重复计数）。
- 重投影流程：目标相机 $c$、时刻 $t$ 光栅化得到颜色与中值深度 $\hat{d}_c$ → 用 $\hat{d}_c$ 反投影目标像素 → 投影到关键帧 → 深度一致性检验 $|z - \hat{d}_\tau| < \epsilon$ → 通过则用关键帧颜色，否则保留面元颜色。
- 静态像素用第一帧，动态像素用最近存储的动态帧；**仅改变颜色，不改变几何或覆盖范围**；不估计运动、不传输表面。

**（5）训练（Sec. 3.5）**
- 每个训练样本选 32 帧窗口 + 一个源相机；监督 4 个时间戳，渲染源视角 + 其余 9 个相机中的 4 个。
- 损失：L1 + SSIM + LPIPS + 深度 + 法线 + 时间损失（匹配帧间图像差异）+ 时间槽特征重建损失 + 占据/KL 损失（沿用 TRELLIS.2）。
- 从 TRELLIS.2 预训练模型初始化，独立训练 30,000 步。

**（6）状态规模计量（Sec. 3.6）**
- 单位：32 位等效值；特征值计 1，占据熵按位除以 32；每个 8 位 RGB 通道保守计为 1 个 32 位值。
- $N = 32|C| + 64|U| + 16|C_{128}| + 32|U_{128}| + B_{occ}/32 + 4|E| + 3 + 3\cdot256^2 + 3|P_{dyn}|$
- 排除共享网络权重与外部相机；这是估算账本，非实测压缩比特流。

## 6. 主要结果与结论

- **定量结果**：在 MCV 随机窗口与 first-32 两种协议下，Sparc4D 在 PSNR、SSIM、LPIPS 上均取得有竞争力的表现，且在状态规模上显著小于像素对齐高斯类方法。在共可见像素设定下，各方法差距收窄，说明主要差异集中在未观测区域的外推与渲染；在均匀填充设定下，Sparc4D 的显式几何与源像素纹理路径体现出优势。
- **与受控 C4G 的对比**：在相同 MCV 训练划分、相同 2,048 高斯输出预算下微调后，Sparc4D 仍保持更优的质量-规模权衡，说明增益并非仅来自输出预算差异，而来自 4D 状态的组织方式。
- **跨数据集结果**：在 DyCheck iPhone 与 Neu3D 上，方法保持可用的重建与渲染质量，验证了显式 4D 状态表示对真实视频的适用性；真实数据上的绝对指标低于合成数据，反映深度估计误差与运动复杂性带来的挑战。
- **核心结论**：将动态场景表示拆解为"跨片段共享的静态隐表示 + 每单元少量时间槽 + 精细外观码 + 存储的源像素纹理"，可以在保持显式 3D 渲染接口的同时，把输出状态压缩到远小于像素对齐方法的规模，从而在紧凑性与保真度之间取得更优折中。

## 7. 局限与讨论

- **时间泛化受限**：动态解码使用"查询时刻观测到的占据"，当前模型仅支持在观测时间戳上的新视角渲染，无法在任意连续时间插值或外推，限制了自由视点视频等应用。
- **依赖外部深度与位姿**：输入深度由 Depth Anything 3 估计，位姿需已知；深度误差会传播到体素化、静态/动态分离与重投影纹理路径。
- **纹理路径的近似性**：源像素纹理仅改变颜色，不改变几何或覆盖范围，也不估计运动或传输表面，因此在视角大幅变化时可能出现纹理与几何不匹配。
- **状态规模为估算**：计量账本非实测压缩比特流，实际存储/传输效率有待验证；RGB 通道按 1 个 32 位值保守计入，可能高估真实成本。
- **静态/动态分离的启发式**：基于"是否被另一帧看穿"与前景掩码扩展，对遮挡频繁或运动复杂的场景可能误判。
- **算力与推理**：未报告推理时延、显存占用与端到端速度，实际部署可行性尚不明确。
- **评估范围**：真实数据集上的对比不充分，缺少与同期动态场景重建方法在真实数据上的同规模比较。

## 8. 总结性评价

Sparc4D 的核心贡献在于把"动态场景的紧凑 4D 表示"这一目标分解为可独立处理的子问题：跨片段共享的静态结构、逐帧压缩的动态时间槽、更细粒度的外观码，以及基于几何重投影的源像素纹理存储。这一分解使得输出状态从像素对齐方法的数亿值量级压缩到远小的规模，同时保留显式高斯面元渲染接口与可复用性。方法在合成大规模基准上验证了质量-规模权衡的优势，并在真实数据上展示了可行性。

其主要不足在于时间维度的表达仍局限于观测时刻、对外部深度/位姿的依赖较强，以及状态规模计量的工程验证不足。总体而言，论文为"可存储、可复用、可渲染的显式动态场景表示"提供了一个结构清晰的设计范式，其价值不仅在于具体指标，更在于明确了哪些信息应当共享、哪些应当随时间变化这一表示层面的问题。
