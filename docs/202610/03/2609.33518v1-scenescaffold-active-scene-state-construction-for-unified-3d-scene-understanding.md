## 摘要
近期的3D大型多模态模型（3D-LMMs）依赖视觉瓶颈，将复杂的3D场景证据压缩为数量有限且与大语言模型（LLMs）兼容的视觉token。然而，当前的视觉瓶颈通常被动地将异构3D证据压缩为同质的以对象为中心的token序列，导致场景的空间组织表征不足。这种表征不足迫使LLM从扁平化的token序列中恢复空间关系，从而在关系密集和空间模糊的场景中导致不稳定的推理。为解决这一问题，我们提出SceneScaffold，一种面向统一3D场景理解的主动场景状态构建框架。SceneScaffold将视觉瓶颈从被动特征压缩器重构为主动场景组织器，在语言推理之前构建角色感知的空间脚手架。具体而言，SceneScaffold将超点级视觉证据组织为具有不同结构角色的场景状态组件：实体状态保留核心对象语义，场景框架状态通过边界和区域锚点维持空间参照，关系状态编码对象-环境交互线索，全局摘要提供紧凑上下文。通过这种角色感知的构建，SceneScaffold在语言推理之前为LLM提供空间组织化的场景表征。在统一3D场景理解任务（包括3D视觉定位、问答和密集描述）上的实验证明了SceneScaffold的有效性，诊断结果进一步表明其适用于关系密集和空间模糊的情况。代码见 https://github.com/lixiangqi707/SceneScaffold。

## Abstract
Recent 3D large multimodal models (3D-LMMs) rely on a visual bottleneck to compress complex 3D scene evidence into a limited number of visual tokens compatible with large language models (LLMs). Current visual bottlenecks, however, often passively compress heterogeneous 3D evidence into a homogeneous object-centric token sequence, leaving the spatial organization of the scene under-represented. This under-representation forces the LLM to recover spatial relations from a flattened token sequence, leading to unstable reasoning in relation-intensive and spatially ambiguous scenes. To address this issue, we propose SceneScaffold, an active scene-state construction framework for unified 3D scene understanding. SceneScaffold reformulates the visual bottleneck from a passive feature compressor into an active scene organizer, constructing a role-aware spatial scaffold before language reasoning. Specifically, SceneScaffold organizes superpoint-level visual evidence into scene-state components with distinct structural roles: entity states preserve core object semantics, scene-frame states maintain spatial references via boundary and region anchors, relation states encode object-environment interaction cues, and a global summary provides compact context. Through this role-aware construction, SceneScaffold provides the LLM with a spatially organized scene representation before language reasoning. Experiments on unified 3D scene understanding tasks, including 3D visual grounding, question answering, and dense captioning, demonstrate the effectiveness of SceneScaffold, while diagnostic results further show its applicability to relation-intensive and spatially ambiguous cases. Code is available at https://github.com/lixiangqi707/SceneScaffold.

# SceneScaffold 论文中文总结

## 1. 核心问题与研究动机

- **背景**：3D 大型多模态模型（3D-LMMs）将 3D 场景表征与大语言模型（LLM）连接，以统一处理视觉定位、问答、密集描述等场景级任务。由于原始 3D 场景点云数量庞大，必须通过"视觉瓶颈"将其压缩为数量受限的视觉 token。
- **核心问题**：当前视觉瓶颈本质上是**被动特征压缩器**，它把异构的 3D 证据（对象表面、场景边界、布局区域、对象-环境关系）压缩为**同质的、以对象为中心的扁平 token 序列**，导致场景的空间组织（边界、占据区域、粗略布局）在有限接口中被严重低估。
- **后果**：LLM 不得不从一维扁平序列中隐式"恢复"空间关系，形成**模态角色错配**——视觉侧只负责筛选证据，语言侧被迫承担补偿性空间结构重建。这在**关系密集**（如"桌子旁边且靠近墙的椅子"）和**空间模糊**（多个同类候选）场景中导致关系混淆、参照漂移和定位不稳定。
- **整体含义**：论文主张视觉瓶颈应从"被动压缩"转向"**主动场景组织**"，在语言推理前明确不同视觉证据的结构角色，构建粗粒度空间参照脚手架。

## 2. 方法论

### 2.1 核心思想
- 在**固定跨模态 token 预算**（默认 K=100）下，将 superpoint 级视觉证据组织为四种角色化场景状态，序列化后送入 LLM。
- 状态分配：75 个残差细节 token + 8 个实体状态 + 8 个场景框架状态 + 8 个关系状态 + 1 个全局场景摘要。

### 2.2 流程与关键技术
- **3D 视觉编码**：3D U-Net 编码器提取 M 个 superpoint 特征 H 及其 3D 质心 U。
- **角色锚定的场景证据构建**：
  - *实体证据*：轻量 MLP 打分 + TopK 选出对象核心证据 P_ent（K_ent=128）。
  - *场景框架证据*：由水平场景范围生成两类锚点——四个边界带（左/右/前/后，边界带比例 0.15）的边界锚点，以及 3×3 网格占据单元的区域锚点。
  - *残差对象缓冲*：保留原视觉连接器的部分输出 Z_res，维持局部细节（对小物体尤其重要）。
- **角色约束的状态归纳**：用可学习角色查询 Q 与证据做**单层交叉注意力**（含残差 + LayerNorm）：
  - 实体状态 S_ent = Φ_ent(Q_ent, P_ent)
  - 框架状态 S_frame = Φ_frame(Q_frame, P_frame)
  - 关系状态 S_rel = Φ_rel(Q_rel, [S_ent; S_frame])，显式建模对象-对象、对象-环境交互
  - 全局摘要 S_scene = φ_scene([Pool(S_ent); Pool(S_frame); Pool(S_rel)])
- **状态序列化与任务使用**：共享投影器 ψ(·) 投影各块，并加可学习角色嵌入；序列固定为 [Z_res, S_ent, S_frame, S_rel, S_scene]。密集掩码解码任务中，用池化状态条件化 [SEG] 查询。
- **角色保持学习目标**：L = L_task + λ_ent·R_ent + λ_frame·R_frame + λ_rel·R_rel
  - *实体语义保持*：实体状态池化后与分数加权实体目标做余弦对齐。
  - *框架覆盖保持*：对边界/区域锚点组计算覆盖度 c_g，用 -log(c_g+ε) 鼓励覆盖多样锚点。
  - *关系几何正则*：以实体证据加权中心生成边界方向标签与区域标签，对关系状态做交叉熵分类。
  - 训练时对残差对象缓冲施加 dropout（p=0.2）作为状态使用正则，推理时关闭。

## 3. 实验设计

- **评价指标**：定位用 mIoU；问答/描述用 CIDEr、BLEU-4、METEOR、ROUGE-L；SQA3D 用 EM 与 EM-R。
- **对比方法**：

  - 通用模型：3D-LLM、LEO、Scene-LLM、Chat-Scene、LL3DA、Spatial 3D-LLM、Grounded 3D-LLM、LSceneLLM、3D-LLaVA、NDTokenizer3D。
- **诊断实验**：构建 Rel.+Amb. 子集（同时含显式空间参照词与多个同类候选），覆盖 4 个数据集（如 ScanRefer 9508 样本中 6329 属该子集）。

## 6. 主要结论与发现

- SceneScaffold 在 5 个基准上整体优于 3D-LLaVA 与 NDTokenizer3D 等统一 3D-LMM：
  - ScanRefer **47.0 mIoU**（较 3D-LLaVA +3.7），Multi3DRefer **47.9 mIoU**（+5.2）。
  - ScanQA **95.8 CIDEr / 16.8 BLEU-4 / 19.0 METEOR / 45.0 ROUGE-L**。
  - SQA3D **55.5 EM / 58.3 EM-R**。
  - Scan2Cap **79.1 CIDEr@0.5 / 37.1 BLEU-4@0.5 / 27.3 METEOR@0.5 / 57.8 ROUGE-L@0.5**。
- **增益集中在定位类任务**，在关系密集与空间模糊的 Rel.+Amb. 子集上依然保持优势（ScanRefer +3.0 mIoU、ScanQA +3.7 CIDEr、Scan2Cap +1.9 CIDEr@0.5）。
- **消融显示各状态角色互补**：去 S_ent 主要损害对象语义（ScanRefer 降至 45.0）；去 S_frame 削弱空间锚定与定位；去 S_rel 影响关系推理与描述（Scan2Cap 降至 75.5）；去 S_scene 影响语言类任务。
- **控制基线均低于完整模型**，说明收益来自"角色化证据 + 状态归纳路径 + 固定预算序列化"的耦合设计，而非单纯增加局部细节。
- **功能干预**表明不同状态不可互换：打乱 S_frame 显著影响定位，打乱 S_scene 对问答/描述影响更大，打乱全部状态退化最大。

## 7. 优点

- **视角新颖**：重新审视 3D-LMM 的视觉瓶颈，提出"模态角色错配"这一诊断性概念，把瓶颈从被动压缩重新定义为主动场景组织。
- **接口设计清晰**：实体 / 框架 / 关系 / 全局四类状态与证据来源、归纳路径一一对应，角色嵌入使 LLM 可区分各块语义。
- **证据锚定明确**：框架状态直接由几何边界与区域锚点驱动，关系状态由实体-框架交互归纳，避免了纯学习查询的模糊性。
- **训练目标轻量且针对性强**：三项角色保持正则分别稳定实体语义、空间覆盖与关系几何，不引入额外复杂结构。
- **实验控制严谨**：消融保持固定 token 预算，附录补充控制基线、功能干预和损失消融，形成多层证据链；诊断子集构建标准明确（空间参照词 + 多同类候选）。
- **可复现性较好**：公开数据、骨干网络、token 分配、超参数、优化器与硬件均有说明，代码承诺开源。

## 8. 不足与局限

- **场景覆盖有限**：仅在室内、静态、ScanNet 风格的场景上评估，未涉及户外、动态环境、长时序具身交互与噪声实时感知。
- **状态表达能力受限**：框架状态仅依赖粗粒度边界与占据区域锚点，关系状态是轻量几何线索，**并非完整场景图或物理拓扑**。
- **可解释性不足**：消融与干预只能证明状态"被使用且互补"，无法完整解释 LLM 内部如何利用各状态。
- **统计严谨性欠缺**：未报告误差棒、置信区间或显著性检验，跨任务一致性仅能部分缓解该问题。
- **对比公平性存在边界**：部分通用模型使用 PC+I 多模态输入，仅作参考；与同模态点云模型的比较虽已限定范围，但不同训练数据与协议差异仍可能影响结论。
- **应用风险**：在安全关键或隐私敏感环境中，3D 理解错误可能导致不安全动作或暴露室内布局；论文建议部署时配合人工监督、不确定性估计、故障安全机制与隐私保护数据处理。
- **未来方向**：自适应状态分配、更强的可解释工具、向户外/动态/实时场景扩展。
